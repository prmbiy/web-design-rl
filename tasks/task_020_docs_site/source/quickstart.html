Your First Pipeline in 5 Minutes

Build a CSV‑to‑Postgres ETL pipeline using Quillforge tasks. By the end you'll have a typed, retry-safe, observable pipeline running on four async workers.

📘 Prerequisites
You'll need Python 3.10+ and a working Quillforge install. If you haven't installed yet, follow the Installation Guide first.

1Initialize the project

Use the bundled quill CLI to scaffold a new project. The init subcommand lays out a conventional directory structure with sample pipelines, task modules, and a starter quill.toml.

bash
$ quill init etl-demo
✓ created etl-demo/
✓ scaffolded pipelines/ tasks/ tests/
✓ wrote quill.toml (v2.4 schema)

The generated tree looks like this:

etl-demo/
etl-demo/
├── pipelines/
│   └── invoices.py
├── tasks/
│   ├── extract.py
│   ├── transform.py
│   └── load.py
├── tests/
│   └── test_pipeline.py
├── quill.toml
└── pyproject.toml
💡 Concept — Project layout
Quillforge enforces a soft convention: tasks/ contains pure functions, pipelines/ composes them into DAGs. The CLI uses this layout for autodiscovery during quill run.

2Define a task

Tasks are async functions decorated with @quill.task. The decorator registers the function with the active Registry and applies retry, timeout, and naming semantics declaratively.

tasks/extract.py
from pathlib import Path
import pandas as pd
import quill


@quill.task(retries=3, timeout=30, name="load_csv")
async def load_csv(path: Path) -> pd.DataFrame:
    """Read a CSV file into a DataFrame, retrying on transient I/O errors."""
    async with quill.io.open(path, mode="rb") as fh:
        data = await fh.read()
    return pd.read_csv(data)
⚠ Heads up
Task functions must be async def. Synchronous functions will raise quill.errors.NotAwaitable at registration time. Use quill.sync_task for blocking work.

3Build the pipeline

Compose your tasks into a Pipeline. Quillforge infers the DAG edges from type hints — the return type of one task is matched against the parameter types of the next.

pipelines/invoices.py
from quill import Pipeline
from tasks.extract import load_csv
from tasks.transform import clean_rows
from tasks.load import write_postgres


etl = Pipeline(
    name="invoice_etl",
    tasks=[load_csv, clean_rows, write_postgres],
    on_failure="halt",
)

if __name__ == "__main__":
    etl.run("data/invoices_2023Q4.csv")
💡 Concept — DAG inference
Because load_csv returns a DataFrame and clean_rows accepts a DataFrame, Quillforge wires them automatically. To force ordering for tasks that share types, pass an explicit depends_on=[…] argument.

4Run it

Launch the pipeline with the CLI. The --workers flag fans the DAG out across an in-process worker pool; for distributed runs see the Workers guide.

terminal
$ quill run etl-demo --workers 4

[12:04:11] INFO  quill.runtime  starting pipeline=invoice_etl run_id=01HF4ZT3
[12:04:11] INFO  quill.worker.0 task=load_csv id=t-001 status=running

[12:04:12] INFO  quill.worker.0 task=load_csv id=t-001 status=success (812ms)
[12:04:12] INFO  quill.worker.1 task=clean_rows id=t-002 status=success (438ms)
[12:04:13] INFO  quill.worker.2 task=write_postgres id=t-003 status=success (1.06s)
[12:04:13] INFO  quill.runtime  Pipeline completed in 2.31s tasks=3 retries=0
🚫 Common pitfall
Never call asyncio.run() from inside a task. Quillforge already manages the event loop; nesting loops will deadlock the worker. Use await directly.
